Common types and code lists
===========================

Common types are defined in ``type.xsd`` (prefix ``typ``).

Record reference: ``typ:refType``
---------------------------------

.. code-block:: xml

   <inv:paymentType>
     <typ:ids>Příkazem</typ:ids>
   </inv:paymentType>

   <typ:country><typ:ids>CZ</typ:ids></typ:country>

``id``
   numeric Pohoda ID (``typ:idType``, integer ≥ 1, generated by Pohoda).
   Takes precedence over the other elements.
``ids``
   text identifier (``typ:idsType``), e.g. currency code ``CZK``,
   pre-accounting abbreviation, centre code.
``extId``
   external system identifier (``typ:extIdType``): ``ids`` +
   ``exSystemName``.

Address: ``typ:address`` / ``typ:myAddress``
--------------------------------------------

Elements: ``company``, ``division``, ``name``, ``city``, ``street``, ``zip``,
``ico``, ``dic``, ``VATPayerType``, ``icDph`` (SK), ``country``, ``phone``,
``mobilPhone``, ``fax``, ``email``... ``partnerIdentity`` in a document may
reference the address book (``typ:id`` / ``typ:extId``) or embed an address
directly; ``myIdentity`` is your own company's identity.

Amounts and VAT rates
---------------------

* Item amounts (``typ:typeCurrencyHomeItem``): ``unitPrice``, ``price``,
  ``priceVAT``; in home currency (``homeCurrency``) or foreign currency
  (``foreignCurrency``).
* Totals (``typ:typeCurrencyHome``): ``priceNone``, ``priceLow``,
  ``priceLowVAT``, ``priceHigh``, ``priceHighVAT`` ...
* ``rateVAT`` (``typ:vatRateType``): ``none``, ``high``, ``low`` (further
  values, e.g. a third reduced rate, see ``type.xsd`` of your version).
* ``payVAT`` – the item price includes VAT (``true``) or not.
* ``calculateVAT`` – VAT calculation method (from the top / bottom).

Payment
-------

``paymentType`` (``typ:paymentType``) is a ``refType`` to a payment type, or
an enumeration such as ``draft`` (transfer order), ``cash``, ``postal``,
``delivery`` (cash on delivery) – check ``type.xsd`` and the Pohoda
settings. ``account`` is the bank account; ``symVar`` / ``symConst`` /
``symSpec`` are the variable, constant and specific symbols.

String lengths
--------------

``typ:string32``, ``string64``, ``string90``, ``string240``... – maximum
field lengths. Overflow causes a validation error.

Document numbers
----------------

The number is assigned from the agenda's number series; a requested number
is given with ``typ:numberRequested`` (see ``numberType``), the number
actually assigned is in ``rdc:producedDetails``. Number series can be
managed with the ``nms:numericalSeries`` agenda.

User parameters and labels
--------------------------

Documents can carry ``labels`` and ``parameters`` (user parameters; the
parameter definitions live in the ``intParam`` / ``parameter`` agenda).
